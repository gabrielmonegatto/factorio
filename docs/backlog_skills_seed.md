## MEMÓRIA 

> Memória é o que transforma agentes stateless em agentes que **aprendem, personalizam e evoluem.**

---

Antes do dump, é importante entender que memória não é uma coisa só:

| Tipo           | Analogia Humana               | O que armazena                                          |
| -------------- | ----------------------------- | ------------------------------------------------------- |
| **Sensorial**  | O que você está vendo agora   | Contexto imediato da conversa/task                      |
| **Episódica**  | Suas memórias de experiências | O que aconteceu em execuções anteriores                 |
| **Semântica**  | Seu conhecimento geral        | Fatos, docs, base de conhecimento                       |
| **Procedural** | Músculo — andar de bike       | Como o agente deve se comportar — prompts, regras, SOPs |

---

### O que Armazenar em Cada Tipo

 🟡 Sensorial (in-context)
> Vive no contexto do LLM. Temporária. Morre quando a sessão acaba.
- Histórico da conversa atual
- Outputs intermediários de steps anteriores
- Estado atual do workflow em execução
- Decisões tomadas nesta sessão

---

 🟠 Episódica (banco vetorial + metadata)
> O agente lembra do que fez antes.
- Histórico de interações com cada cliente/lead
- Resultados de campanhas anteriores
- Erros cometidos e como foram resolvidos
- Feedbacks recebidos sobre outputs anteriores
- Quais abordagens funcionaram por segmento
- Histórico de decisões do orchestrator
- Logs de execução de workflows com outcome

---

 🔵 Semântica (RAG — base de conhecimento)
> O que a fábrica sabe sobre o mundo e sobre o negócio.
- Documentos da empresa (pitch, produto, pricing, ICP)
- SOPs e processos internos
- Base de conhecimento do setor/mercado
- Transcrições de calls de vendas
- Conteúdos produzidos anteriormente
- Concorrentes e battlecards
- FAQs e objeções mapeadas
- Dados de clientes estruturados

---

 🟢 Procedural (system prompts + regras + fine-tuning)
> Como o agente se comporta — seu "jeito de ser".
- Tom de voz e personalidade da marca
- Regras de negócio fixas ("nunca ofereça desconto acima de 20%")
- Restrições éticas e de compliance
- Preferências aprendidas do usuário ao longo do tempo
- Workflows preferidos por tipo de situação
- Critérios de qualidade de output

---

### Onde Fisicamente Armazenar

| Tipo       | Tecnologia                                                   |
| ---------- | ------------------------------------------------------------ |
| Sensorial  | Contexto do LLM (in-memory)                                  |
| Episódica  | Pinecone / Chroma / pgvector + PostgreSQL para metadata      |
| Semântica  | Pinecone / Chroma / pgvector + S3 para arquivos raw          |
| Procedural | Arquivos de configuração / system prompts versionados no Git |

---

### Operações de Memória (voltando às tools)

```
memory_write        → salva nova informação com embedding + metadata
memory_read         → busca semântica por relevância ao contexto atual
memory_update       → atualiza informação existente
memory_delete       → remove informação obsoleta ou incorreta
memory_summarizer   → comprime memórias antigas em resumos densos
context_builder     → monta contexto ideal antes de cada execução
memory_ranker       → dado N memórias recuperadas, rankeia por relevância
```

---

### Padrões de Uso na Fábrica

### Padrão 1 — Memória por Entidade
Cada cliente, lead ou parceiro tem seu próprio "dossiê" na memória:
```
{cliente_id} → histórico de interações
             → preferências identificadas  
             → estágio no relacionamento
             → últimas ações tomadas
             → sentimento geral detectado
```

### Padrão 2 — Memória por Agente
Cada agente aprende com suas próprias execuções:
```
{agente_id} → outputs que foram aprovados vs rejeitados
            → estratégias que funcionaram por contexto
            → erros cometidos e correções aplicadas
```

### Padrão 3 — Memória Global da Fábrica
Conhecimento compartilhado entre todos os agentes:
```
global → positioning e mensagem central da empresa
       → ICP atualizado
       → métricas de referência atuais
       → prioridades estratégicas do momento
```

---

### O Que a Memória Habilita na Prática

- Agente de vendas que lembra que aquele lead mencionou budget restrito há 3 meses
- Content agent que nunca repete um ângulo já explorado
- Outreach agent que adapta tom por persona automaticamente
- Orchestrator que aprende quais squads performam melhor por tipo de objetivo
- Customer success agent que detecta padrão de churn antes de acontecer
- Fábrica inteira que fica mais inteligente a cada ciclo

---

### A Pergunta que Você Fez Antes — Memória Precisa de Backlog?

**Sim, mas diferente dos outros módulos.**

Não é um backlog de "construir memórias" — é um backlog de **infraestrutura e política de memória:**

- Definir schema de entidades (cliente, lead, agente, campanha)
- Escolher e configurar banco vetorial
- Implementar as tools de memória
- Definir política de retenção (o que guardar, por quanto tempo)
- Definir política de atualização (quando sobrescrever vs acumular)
- Criar Memory Manager Agent

## OBSERVABILIDADE 

> Observabilidade é o que transforma a fábrica de uma caixa preta em um sistema **auditável, debugável e evoluível.**

---

### Os 3 Pilares da Observabilidade

| Pilar       | Pergunta que responde      | Exemplo                                 |
| ----------- | -------------------------- | --------------------------------------- |
| **Logs**    | O que aconteceu?           | "O agente chamou a tool X às 14:32"     |
| **Traces**  | Como aconteceu?            | "O workflow levou 4 steps, falhou no 3" |
| **Metrics** | Quão bem está acontecendo? | "Taxa de sucesso de agentes: 94%"       |

---

### O que Observar em Cada Camada

 🔵 Workflows
- Status de cada execução (success, failed, running, retrying)
- Tempo de execução por step e total
- Taxa de falha por workflow
- Frequência de execução vs planejado
- Custo computacional por execução
- Histórico de retries e motivos
- Filas e backlogs acumulados

 🟠 Agentes
- Número de steps por execução
- Tokens consumidos por execução (custo $)
- Quais tools foram chamadas e com qual frequência
- Taxa de sucesso de tool calls
- Tempo de resposta do LLM por call
- Qualidade do output (score humano ou automatizado)
- Loops infinitos ou execuções travadas
- Hallucinations detectadas

 🟡 Squads
- Performance coletiva por objetivo
- Gargalos — qual agente atrasa o squad
- Taxa de retrabalho entre agentes
- Coerência de outputs entre agentes do mesmo squad
- Human-in-the-loop: quantas aprovações, quantas rejeições

 🔴 Memória
- Taxa de hit vs miss em buscas vetoriais
- Qualidade de recuperação (retrieved mas irrelevante?)
- Crescimento do banco vetorial ao longo do tempo
- Memórias mais acessadas vs nunca acessadas
- Latência de operações de memória

🟢 Tools
- Taxa de sucesso por tool
- Latência média por tool
- Erros mais frequentes por tool
- Custo por chamada (APIs pagas)
- Tools mais usadas vs nunca usadas

---

### O que Capturar em Cada Evento

Todo evento na fábrica deve ter:

### Stack de Observabilidade

| Camada        | Ferramenta           | Para quê                                     |
| ------------- | -------------------- | -------------------------------------------- |
| **Agentes**   | LangSmith            | Traces de agentes, evals, debug de LLM calls |
| **Workflows** | Prefect UI           | Status, logs e histórico de flows            |
| **Métricas**  | Prometheus + Grafana | Dashboards de performance e alertas          |
| **Logs**      | Loki ou Datadog      | Logs centralizados e pesquisáveis            |
| **Erros**     | Sentry               | Exceções com stack trace completo            |
| **Custo IA**  | LangSmith / Helicone | Token usage e custo por agente/workflow      |

### Alertas que a Fábrica Precisa

```
🔴 CRÍTICO
- Workflow de missão crítica falhou 3x seguidas
- Agente em loop infinito detectado
- Custo de API excedeu threshold diário
- Tool com 100% de falha nos últimos N calls

🟠 ATENÇÃO  
- Taxa de sucesso de agente caiu abaixo de 80%
- Latência média de workflow dobrou vs ontem
- Fila de execuções acumulando sem consumo
- Memory hit rate abaixo de 60%

🟡 INFORMATIVO
- Novo recorde de execuções simultâneas
- Tool X não é chamada há 7 dias (obsoleta?)
- Custo mensal projetado X% acima do mês anterior
```

### Padrões de Observabilidade na Fábrica

### Padrão 1 — Trace Distribuído
Cada objetivo de alto nível gera um `trace_id` único que propaga por todos os agentes, tools e workflows envolvidos. Você consegue ver a jornada completa de ponta a ponta.

### Padrão 2 — Eval Contínuo
Outputs de agentes são periodicamente avaliados por um **Quality Check Agent** ou por humanos. Score é salvo e alimenta melhoria de prompts.

### Padrão 3 — Cost Tracking
Cada execução sabe quanto custou. Você consegue responder: *"Quanto custa produzir um artigo de blog com a fábrica?"*

### Padrão 4 — Feedback Loop
```
Observabilidade detecta problema
        ↓
Alerta dispara
        ↓
Error Handler Agent investiga
        ↓
Correção aplicada (automática ou humana)
        ↓
Memória atualizada com o aprendizado
        ↓
Fábrica fica mais resiliente
```

---

### Observabilidade Precisa de Backlog?

**Sim, e é o primeiro backlog a executar.**

Sem observabilidade desde o dia 1 você está voando cego. A ordem é:

```
1. Estrutura de logging padronizada (o schema acima)
2. Integração LangSmith
3. Prefect UI configurado
4. Sentry para erros
5. Alertas críticos
6. Dashboards de custo
7. Eval pipeline
8. Grafana para métricas avançadas
```
